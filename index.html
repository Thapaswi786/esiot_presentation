1. Introduction and learning objectives

GSM (Global System for Mobile Communications) is a cellular communication standard. SMS (Short Message Service) lets a device submit a short text message through a mobile network for delivery to a recipient. In an embedded system, a microcontroller sends commands to a GSM modem over a serial interface; the modem handles SIM/network access and SMS submission.

By the end, you should be able to

  • Describe the GSM network elements involved in SMS.
  • Connect a controller and modem using safe UART logic levels and power.
  • Use AT commands to check readiness and submit a text message.
  • Calculate UART bit timing and transmission time.
  • Diagnose common SIM, network, wiring and power faults.

Prerequisites

  • Digital logic and serial communication
  • Microcontroller GPIO and Arduino IDE basics
  • Voltage, current, grounding and regulated supplies
  • Basic cellular network concepts
Key distinction: an OK or +CMGS response usually indicates command acceptance or SMS submission—not proof that the recipient has read or even received the message.

C. SMS sequence

  1. Controller opens UART and sends AT.
  2. Modem responds; controller checks SIM readiness and registration.
  3. Controller selects text mode and starts AT+CMGS.
  4. Modem prompts with >; controller sends body and Ctrl+Z.
  5. Modem reports submission status; network processes the SMS.
  6. Recipient delivery depends on routing, service and availability.

5. Working principle, state flow and simulation

  1. Initialize: start controller UART at the configured baud rate.
  2. Check modem: send AT and wait for a valid response.
  3. Check SIM: use AT+CPIN?; resolve a PIN request securely if required.
  4. Register: query registration with a supported command such as AT+CREG?. A SIM-ready response alone does not prove registration.
  5. Check signal: AT+CSQ gives a reported signal-quality value; 99 often means unknown/not detectable, not “99% signal.”
  6. Configure SMS: set text mode with AT+CMGF=1 where supported.
  7. Submit: issue AT+CMGS, wait for the prompt, send message text and Ctrl+Z (ASCII 26).
  8. Interpret result: read +CMGS/OK or an error. A delivery report is separate and may not be available.

Arduino UNO example (SoftwareSerial)

Use a level-compatible modem, separate suitable supply, shared ground, correct antenna and an active SIM. Replace the destination placeholder with a number you are authorized to message. This example waits for the prompt but is intentionally a basic teaching example, not production-grade response parsing.

#include <SoftwareSerial.h>

// UNO D10 receives GSM TX; UNO D11 transmits to GSM RX.
// Confirm logic-level compatibility and the exact module power requirements.
SoftwareSerial gsm(10, 11); // RX, TX
const char DESTINATION[] = "<DESTINATION_NUMBER>";

void sendAT(const char *cmd, unsigned long waitMs = 1000) {
  gsm.println(cmd);
  unsigned long start = millis();
  while (millis() - start < waitMs) {
    while (gsm.available()) Serial.write(gsm.read());
  }
}

void setup() {
  Serial.begin(9600);  // USB serial monitor
  gsm.begin(9600);     // Must match modem UART configuration
  delay(1500);
  sendAT("AT");
  sendAT("ATE0");
  sendAT("AT+CPIN?");
  sendAT("AT+CREG?");
  sendAT("AT+CMGF=1");
  gsm.print("AT+CMGS=\\"");
  gsm.print(DESTINATION);
  gsm.println("\\"");
  // Wait for '>' prompt in a robust implementation before sending body.
  delay(1000); // Simple demonstration only; prompt timing is not guaranteed.
  gsm.print("GSM SMS test from embedded controller");
  gsm.write(26); // Ctrl+Z / ASCII 26 submits the SMS
  delay(5000);
  while (gsm.available()) Serial.write(gsm.read());
}
void loop() {
  // Add event logic, bounded retries, and response parsing as required.
}
For robust firmware, replace fixed delays with timeouts and response parsing; verify the > prompt, +CMGS and error responses. Do not repeatedly send messages on every loop iteration.

7. Equations and engineering calculations

UART bit duration

Tb = 1 / Rb

T_b is seconds per bit; R_b is bits per second for binary UART. At 9600 bps: 104.17 μs/bit. At 115200 bps: 8.68 μs/bit.

UART frame time

T ≈ (N × F) / Rb

N is data bytes; F is frame bits per byte. For 8-N-1, F = 10. This estimates serial-wire time, not cellular delivery latency.

8-N-1 payload efficiency

η = 8/10 × 100% = 80%

Eight payload bits are sent using ten total bits: one start and one stop bit, no parity. This is UART framing efficiency, not GSM network efficiency.

Electrical power

P = V × I

Power in watts equals voltage in volts multiplied by current in amperes. Use the actual module's voltage and peak/burst-current specification for supply design.

SMS capacity

A single SMS commonly holds up to 160 characters when GSM 7-bit default alphabet encoding applies, or 70 UCS-2 characters for many Unicode messages. Concatenation headers reduce per-segment capacity; special characters, language tables and operator behaviour can change the count. These are not limits for every arbitrary string.

8. Solved numerical problems

Example 1 — Bit duration at 9600 bps

Given: R = 9600 bits/s. Find: bit duration.

Formula: T = 1/R = 1/9600 s = 0.00010417 s ≈ 104.17 μs.

Example 2 — 50 bytes at 9600 bps, 8-N-1

Each byte consumes 10 serial bits. Total = 50 × 10 = 500 bits. Time = 500/9600 = 0.05208 s ≈ 52.1 ms, excluding software gaps and response time.

Example 3 — Compare 9600 and 115200 bps for 50 bytes

At 9600: 500/9600 = 52.08 ms. At 115200: 500/115200 = 4.34 ms. Ideal wire-time ratio = 12×. This does not mean the cellular SMS is delivered 12× faster.

Example 4 — SMS character capacity

Assume a message uses only GSM 7-bit default alphabet characters and is 150 characters long. Since 150 ≤ 160, it fits in one standard single-part SMS under that assumption. If the message requires UCS-2 and has 75 characters, it exceeds the common 70-character single-part limit and generally needs concatenation.

Example 5 — Illustrative power calculation

For a hypothetical supply condition of 4.0 V and 2.0 A instantaneous current, P = 4.0 × 2.0 = 8 W instantaneous. This is a calculation example, not a universal SIM800L/SIM900A supply specification. Use the exact module documentation and account for current bursts, wiring drop and regulator stability.

GATE-style shortcut

For 8-N-1 UART, quickly estimate time as 10 × number of bytes ÷ baud rate. At 10,000 bps, 100 bytes take about 0.1 s of UART framing time. Do not use this to estimate network registration or SMS delivery time.

9. GATE-style practice questions

Original practice questions for revision; these are not represented as actual previous-year GATE questions.

Q1 • Easy — What does SMS stand for?

Answer: Short Message Service. It is a store-and-forward messaging service.

Q2 • Easy — Which element commonly stores and forwards SMS messages?

Answer: SMSC. It may retain a message and retry delivery according to network rules.

Q3 • Easy — For binary UART, bit rate is 9600 bps. What is bit duration?

Answer: 1/9600 = 104.17 μs.

Q4 • Moderate — How many bits are sent per byte using 8-N-1 framing?

Answer: 10 bits: one start, eight data and one stop bit.

Q5 • Moderate — What is the correct UART wiring?

Answer: Controller TX to modem RX and controller RX to modem TX, with common ground and compatible logic levels.

Q6 • Moderate — What does AT+CMGF=1 usually select?

Answer: SMS text mode, where supported.

Q7 • Moderate — Does AT+CPIN? returning READY prove network registration?

Answer: No. It indicates SIM readiness; registration must be checked separately.

Q8 • Moderate — A 20-byte 8-N-1 payload at 9600 bps takes approximately how long?

Answer: 20 × 10 / 9600 = 20.83 ms, excluding software gaps.

Q9 • Difficult — Why might +CMGS be shown while recipient delivery is unconfirmed?

Answer: It commonly confirms submission to the network/modem path, not final recipient delivery. A supported delivery report is a separate mechanism.

Q10 • Difficult — The modem resets when sending. Name the first hardware checks.

Answer: Supply voltage at the module during bursts, supply peak-current capability, regulator stability, wiring/ground drops, antenna and board-specific power requirements.

Q11 • Moderate — Which setting is normally irrelevant to basic SMS-only operation?

Answer: APN settings are typically for packet-data services such as GPRS, not ordinarily required for basic SMS submission.

Q12 • Difficult — Why may a modem fail to register despite a working SIM?

Answer: Coverage, incompatible frequency bands, unsupported/retired network technology, account provisioning, antenna, SIM/service restrictions or local operator support.

12. Core electronics and embedded systems interview questions

1. What are GSM and SMS?

GSM is a cellular system standard; SMS is a short-message service supported by a network. A module provides the embedded controller an interface to cellular services.

2. What is the role of a GSM module?

It handles cellular radio/network access, SIM interaction and modem commands, allowing a microcontroller to submit SMS or use other supported services.

3. What are AT commands?

Commands sent over a control interface to configure/query a modem. The controller should parse responses and errors rather than assuming every command succeeded.

4. How do you send an SMS?

Check modem, SIM and registration; set AT+CMGF=1; issue AT+CMGS with destination; wait for prompt; send body and Ctrl+Z; inspect response and any supported delivery report.

5. Why cross-connect TX and RX?

One device's transmit output must feed the other device's receive input. Ground references must also be shared for ordinary UART wiring.

6. Why might an external supply be required?

Cellular transmission can create short current bursts. A controller-board regulator may not sustain those bursts without voltage droop or resets. Follow the exact module specification.

7. Text mode versus PDU mode?

Text mode is simpler for basic human-readable messages. PDU mode uses encoded protocol units and provides more control over encoding and message parameters, but requires correct encoding/decoding.

8. How do you check registration?

Use a supported command such as AT+CREG? for classic circuit-switched registration and interpret the returned status according to the modem manual. Some technologies expose other registration commands too.

9. Why can OK appear without delivery?

OK may confirm that a command was accepted. +CMGS generally reports submission status. Network delivery and recipient availability are separate; request/check a supported delivery report if needed.

10. How do you debug a failed SMS?

Check power during transmit, antenna, SIM readiness, registration, signal, bands/network support, UART wiring/levels/baud, SMS mode, destination format, service restrictions and exact CMS error.

11. UART baud rate versus cellular speed?

UART baud controls the local serial link between controller and modem. Cellular air-interface and network processing use different mechanisms; UART timing cannot predict SMS delivery latency.

12. What if the module restarts during sending?

Measure supply voltage at the module under load, verify peak-current capability and low-resistance wiring, inspect grounding and regulator transient response, and check for shorts or thermal issues.

13. Can a 5-V UNO TX connect directly to any modem RX?

No. Logic thresholds vary. Check both datasheets and use a suitable level shifter or divider where required. ESP32 GPIOs are not 5-V tolerant.

14. What are practical reliability measures?

Use timeouts, bounded retries with backoff, registration checks, event IDs or duplicate prevention, persistent status logging, and avoid sending repeated alerts every loop iteration.

15. Follow-up: how would you test without cellular hardware?

Mock the modem's UART responses to validate state logic and error handling, then test on physical hardware with a supported SIM/network. A mock test cannot prove radio registration or real SMS delivery.

15. Quick revision sheet

Remember

  • TX connects to RX; RX connects to TX.
  • Common ground is needed for standard UART.
  • SIM ready ≠ network registered.
  • Command accepted ≠ recipient delivered.
  • Use Ctrl+Z (ASCII 26) to submit the text body after the prompt.
  • Power supply must handle modem peak current.
  • Check bands and local network technology before selecting a module.

Formula sheet

  • Tbit = 1 / baud
  • T ≈ N × frame bits / baud
  • 8-N-1 frame = 10 bits per byte.
  • 8-N-1 payload efficiency = 80%.
  • P = V × I
  • UART timing does not estimate SMS delivery latency.

  4. Signal: AT+CSQ
